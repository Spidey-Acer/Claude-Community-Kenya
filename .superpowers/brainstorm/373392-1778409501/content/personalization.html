What we DON'T personalize (anti-patterns)
  • Navigation — never hide nav items by audience. Discoverability > personalization.
  • Search results — show all matches, not filtered by audience.
  • Detail pages (event, blog, project) — same content for everyone. Only the recommendation block on top adapts.
  • Sign-up forms — never block based on audience. A "wrong-audience" user must still be able to apply.
  • Pricing/access — N/A here, but as a principle: never gate by audience.
Recommendation engine — simple ranking, no ML

src/lib/recommendations.ts — pure function, no external deps. Each event/resource has audiences: Audience[] and optional intents: Intent[] tags (manual, set in admin). Score: 

score =
  (audience match)         * 5 +
  (intent match)           * 3 +
  (city match)             * 2 +
  (experience appropriate) * 2 +
  (recency, weeks until)   * (1 / weeks_away) +
  (featured flag)          * 1

Top 3 by score. Cached per-audience for 5 minutes. Falls back to "featured" if no items match.
