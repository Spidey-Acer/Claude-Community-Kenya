Engineering decisions baked in
  • Tool calling for structured extraction. Claude streams natural text AND silently calls a record_visitor tool with {audience, intent, experience, name?, city?}. Conversation feels human; backend gets clean data.
  • Hard 5-turn cap. If Claude hasn't extracted enough by turn 5, it lands gracefully with whatever it has + best-guess defaults.
  • Skip always visible. "Skip and explore →" link top-right at every turn. Defaults to audience=dev, no DB write, no personalization.
  • Real DB content in recommendations. Claude is given live event/blog/community data via context injection, so recommendations are real (not hallucinated).
  • Off-topic redirect. If user asks general questions ("how do I use Claude Code?"), Claude says: "Happy to dig in once you're inside — let's finish setup first?" Then offers to continue chatting via the regular ChatWidget after.
  • Rate limit: 5 conversations/hr per IP. Lower than general chat. One real onboarding per visitor is enough.
  • Fallback chain. API down → static chip-only wizard. Tool call failure → conversation continues, defaults applied. Total system never blocks the user from entering the site.
